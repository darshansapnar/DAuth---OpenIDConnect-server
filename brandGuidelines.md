# DAuth Brand Guidelines

## Brand Personality

DAuth is a developer-first authentication platform.

The design should communicate:

- Trust
- Simplicity
- Reliability
- Security
- Professionalism

Avoid looking like an AI-generated landing page.

---

# Design Inspiration

Inspired by

- GitHub
- Clerk
- Stripe Dashboard
- Vercel
- Linear
- Supabase

Do NOT copy any existing UI.

Only take inspiration from layout quality and usability.

---

# Design Philosophy

Minimal.

Professional.

Elegant.

Functional.

Every UI element should have a purpose.

Remove unnecessary decoration.

Fallback

Typography should prioritize readability.

---

# Layout

Prefer

- Left-aligned content
- Clear hierarchy
- Comfortable spacing
- Consistent padding
- Responsive grids

Avoid

- Giant hero sections
- Excessive whitespace
- Centering everything

---

# Components

Create reusable components.

Examples

- Button
- Input
- Card
- Modal
- Table
- Badge
- Alert
- Dropdown
- Sidebar
- Navbar
- Toast
- Tabs
- Pagination

Reuse components instead of rebuilding them.

---

# Forms

Forms should:

- Validate clearly
- Show inline errors
- Have obvious primary actions
- Support keyboard navigation

---

# Tables

Professional tables with

- Sorting (when appropriate)
- Search
- Empty states
- Status badges
- Action menus

---

# Dashboard

Dashboard style:

Professional SaaS.

Use

- Sidebar
- Top navigation
- Statistic cards
- Activity feed
- Data tables

No excessive decoration.

---

# Icons

Use a consistent icon library.

Icons should remain simple.

Avoid decorative illustrations.

---

# Animations

Animations should be subtle.

Allowed

- Fade
- Hover
- Dropdown
- Modal transition
- Loading skeleton
- Toast animation

Avoid

- Floating blobs
- Continuous movement
- Bounce
- Spin (except loading)
- Large parallax effects

---

# Accessibility

Maintain strong color contrast.

Use visible keyboard focus states.

Provide labels for interactive elements.

Avoid relying on color alone to communicate meaning.

---

# Empty States

Every empty state should guide the user.

Example

"No OAuth clients yet."

Include a clear action button.

---

# Error States

Errors should:

- Explain what happened.
- Suggest how to fix it.
- Avoid technical jargon unless useful.

---

# Responsive Design

Desktop first.

Then optimize for tablet and mobile.

Do not simply stack everything vertically.

Adjust layouts thoughtfully.

---

# Overall Goal

Every screen should feel like part of the same product.

Prioritize clarity, consistency, and usability over flashy effects.

If a design choice improves aesthetics but harms usability, choose usability.
